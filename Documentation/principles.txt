What the audience needs to remember (3 ideas only)If they leave with only three points, aim for:The problem is real — paper collection creates risk, delay, and opacity for MFIs in CEMAC. Everything else supports these three. If a slide does not serve one of them, cut it.2. Principles for a good, concise, efficient talkContentOne idea per slide. Title = the message, not a topic label (“Cash still travels with the agent” beats “Family A limits”). Full words first, then abbreviation (you already fixed this: Microfinance Institution (MFI), Core Banking System (CBS)…). Story before score. Numbers (2.10, 2.65, 4.50) only after the human story. Honest wording. “institutional cash-risk control via escrow” over “zero cash” — builds credibility. Architecture once. One diagram; explain top → bottom: phone → gateway → core → middleware → bank system. No component laundry list. VisualsBeige / off-white background, dark text (readable in a bright room). Large titles, little body text (max ~6 short lines). Same gold numbers for steps (1, 2, 3…) — easy to follow. phone-shaped mock or simple icons rather than dense tables. Benchmark: one small score row or three cards (POS / Apps / USSD), rather than matrices. DeliverySpeak to the problem owner (director, cashier, supervisor)and not only to engineers. Translation of tech terms:Offline-first → “works when the network is dead on the market” Escrow lockout → “app stops collecting when the guarantee is used up” Middleware → “translator between our app and the bank software” Point forward: end each block with “next we show how MICROFI answers this”. Do not read the slides. Slides = anchors; you tell the story. Pause after the architecture slide — invite one clarifying question if time allows.
