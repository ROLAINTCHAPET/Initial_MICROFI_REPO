Two real risks before the MVP deadline

Everything else tagged MVP has working code behind it. These two are the only ones with a genuine, specific gap against their own requirement text.

  • FR-06 · No QR scan channel3 of the 4 required client-identification methods work (member number, phone, name). Camera-based QR scanning has no package installed and no UI anywhere in the mobile collection flow.
  • FR-07 · Offline queue not encryptedQueued collections (client, amount, GPS, denominations) sit in plain shared_preferences while offline. flutter_secure_storage is already a dependency — currently used only for the session token — and is the natural fix.
